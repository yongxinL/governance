# 12. Planning and Cross-Specification Delivery

**Part II** · Owns: native feature planning, plan boundaries, cross-specification plan triggers, multi-release and migration coordination, infrastructure transitions, no competing plan hierarchy.

## 12.1 Native feature planning

Every feature plan is the native Spec Kit plan produced by `speckit.plan` inside the feature's `specs/` directory, with its native supporting artifacts (research, data model, contracts, quickstart as generated by the pinned version). The owner approves the plan before tasks are generated.

## 12.2 Plan boundaries

A plan derives from the approved specification and constitution, references constraining ADRs, maps its components to requirement IDs, and introduces no new requirements or speculative scope. If planning reveals a requirement problem, return to clarify or a controlled specification change.

## 12.3 Cross-specification delivery plans

Use a cross-specification delivery plan only when one native plan is insufficient:

- Work spanning multiple specifications or multiple releases.
- Multiple systems requiring coordinated change.
- Governance adoption or migration of an existing project.
- Infrastructure transitions.
- Data migrations.
- Coordinated deprecations.
- Other genuinely cross-cutting initiatives.

Path: `docs/architecture/delivery-plan-<kebab-title>.md`, indexed in `docs/architecture/README.md`. Template: [`cross-specification-delivery-plan-template.md`](../project-template/docs/templates/cross-specification-delivery-plan-template.md).

## 12.4 Content and limits

A delivery plan coordinates: objective, participating specifications and releases, dependency order, milestones, migration and rollback windows, risks, and owner checkpoints. It never contains feature tasks or restates requirements; each participating feature keeps its native plan and tasks.

## 12.5 No competing plan hierarchy

No `docs/plans/` directory exists. No phase documents, roadmaps, or tool-generated plans act as authority for feature work. External roadmaps may exist for communication but are not governed authority.
